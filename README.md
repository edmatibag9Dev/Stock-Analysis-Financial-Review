# Stock Analysis Financial Review

## 1. Project Overview

A fundamental and technical investment-analysis workflow for publicly traded equities. For each ticker it produces a professional investment memo (`.docx`) and, where the name warrants one, a valuation model (`.xlsx`) with a 3-scenario DCF, plus a technical chart (`.png`). Every deliverable is generated by a build script that lives beside its output, so any analysis can be regenerated or audited from source.

The repository is organized as one dated folder per analysis: `$TICKER/$TICKER-{YYYY-MM-DD}/`. A re-run never overwrites a prior analysis — it creates a new dated folder, so the full history of a thesis stays intact and revisions are traceable.

## 2. Purpose

Retail investment research usually leaves no audit trail. A verdict gets formed, acted on, and then forgotten — leaving no way to ask later whether the reasoning was sound or merely lucky. This repo exists to fix that. Each analysis records the numbers, the assumptions behind them, and the verdict at a moment in time, so a later re-run can be compared against the earlier one and the delta explained.

That comparison is the point. The August 2026 `$BROS` update, for example, upgraded HOLD to ACCUMULATE only after rebuilding the June DCF from scratch — which exposed an internal inconsistency in the June memo's published intrinsic values. Without a preserved June folder, that error would have propagated silently. The same pattern caught three-WACC methodology violations in the June `$NOW` and `$PLTR` models, both corrected to a single WACC on refresh.

This is Ed's own research on public equities. It is not investment advice.

## 3. Features

**Dated, immutable analysis folders.** Each run lands in `$TICKER/$TICKER-{YYYY-MM-DD}/`. Prior runs are never edited; superseded ones move to `$TICKER_Archive/`. The folder name is the lookup key — consumers locate an analysis by ticker and date alone.

**11-section investment memo (`.docx`).** Business snapshot, management and governance, bull case, bear case, base case, DCF valuation, Rule of 40 (SaaS names), peer comps, technical setup, options overlay, and a verdict with an explicit monitoring plan — including the specific metrics that would trigger an upgrade or a downgrade.

**4-sheet valuation model (`.xlsx`).** Historical financials, 5-year projections, a DCF waterfall across bull/base/bear, and an options-strategy reference sheet, plus a Leadership_Scorecard block on the Rule_of_40 sheet.

**Single-WACC 3-scenario DCF.** All three scenarios discount at one WACC; only the operating assumptions vary between them. Using a different discount rate per scenario artificially widens the spread and is treated as a methodology violation. Pre-profitable companies use an EBITDA-terminal approach instead of perpetuity growth.

**Technical overlay.** SMA 20/50/200, RSI, and IV rank, used both to time entries and to size the options overlay.

**Options strategy overlay.** Cash-secured puts, covered calls, and bull call spreads, selected by where price sits relative to DCF intrinsic value and by whether implied volatility is rich or cheap.

**Two-store model.** Google Drive is the system of record and holds *every* analysis, including one-look passes and AVOIDs, so cross-ticker comparison has full context. This repo is the lean active working set — a ticker is committed only when Ed has an open position, an active options trade, or a live watchlist entry.

**Packaged skill.** `stock-analysis.skill` drives the whole workflow end to end for any ticker: research, model build, memo build, and Drive upload.

Inside each dated analysis folder:


Build scripts keep plain names (no `$`) for shell-safety and must quote their output paths.

## 5. How to Use

**Prerequisites:**

```bash
pip install openpyxl --break-system-packages
npm install -g docx
```

**Regenerate a deliverable** — run the script from inside its own analysis folder:

```bash
cd '$BROS/$BROS-2026-08-10' && node create_bros_memo.js && python3 build_bros_model.py
cd '$FSLY/$FSLY-2026-08-11' && node create_memo.js       && python3 build_model.py
cd '$FSLY/$FSLY-2026-06-08' && node create_fsly_memo.js  && python3 build_fsly_model.py
cd '$PLTR/$PLTR-2026-06-05' && python3 build_model.py
cd '$NOW/NOW-2026-06-05'    && node create_now_memo.js
cd 'SG/SG-2026-06-05'       && node create_sg_memo.js    && python3 build_sg_model.py
cd 'TRMB/TRMB-2026-06-11'   && node create_trmb_memo.js  && python3 build_trmb_model.py
```

Single-quote the paths — an unquoted `$BROS` is read by the shell as an empty variable.

**Start a new analysis.** Invoke `stock-analysis.skill` with a ticker. It researches, builds the model and memo into a fresh `$TICKER-{YYYY-MM-DD}/`, and uploads to Drive. Then update the analyses table below, and decide repo-vs-Drive: commit only if the ticker is an active position or watchlist entry. To add an approved ticker past the default `.gitignore` rule, force-add it once — it stays tracked thereafter:

```bash
git add -f '$TICKER/'
```

**Expected output:** a memo `.docx` with all 11 sections, a model `.xlsx` with 4 sheets, and — where the analysis includes technicals — a chart `.png`, all inside the dated folder.

No environment variables or API keys are required.

## 7. Data Sources

- **SEC EDGAR** (https://www.sec.gov/edgar) — 10-Q and 8-K filings for revenue, margins, share count, and balance-sheet items. No API key; public rate limits apply.
- **Company investor relations** — quarterly press releases and guidance, cited by date in each memo.
- **stockanalysis.com** (https://stockanalysis.com) — price history, market cap, enterprise value, 52-week range.
- **GuruFocus** (https://www.gurufocus.com), **ValueInvesting.io** (https://valueinvesting.io), **AlphaSpread** (https://www.alphaspread.com) — peer-comp valuation multiples.
- **investing.com** (https://www.investing.com) and **CNBC** (https://www.cnbc.com) — earnings-day price action and after-hours quotes.
- **Options chains** — implied volatility and IV rank, read from the brokerage platform at analysis time; strikes and premiums quoted in each memo are point-in-time.

All sources are public and free. No credentials, keys, or paid feeds are used, and none are stored in this repo.

## 8. Known Limitations

- **Point-in-time only.** Prices, IV, and premiums are captured on the analysis date and are stale immediately. Nothing in a dated folder auto-refreshes.
- **Manual table sync.** The analyses table above is updated by hand. Nothing validates that it matches the memos on disk.
- **Two runs have no committed build script.** `$NOW/NOW_Investment_Memo_2026-07-23.docx` and `$PLTR/$PLTR-2026-08-03/` ship deliverables without the generators that produced them, so those two cannot be regenerated from this repo.
- **`$NOW` July refresh breaks the data contract.** Its files sit at the ticker root rather than in a `$NOW-2026-07-23/` folder, so date-based folder lookup misses it.
- **Legacy naming persists.** `SG` and `TRMB` have not migrated to the `$TICKER` standard, and the `$NOW` and `$PLTR` June folders retain some non-`$` filenames.
- **Repo is a partial view.** Drive-only tickers such as `$NUAI` are absent by design. The repo is not a complete record of the research.
- **`.gitignore` fights the naming standard.** `/$*/` ignores every `$`-prefixed ticker folder, so each approved ticker needs a one-time `git add -f`. Forgetting it means a new analysis silently never reaches the repo.
- **Build scripts require a desktop session.** They will not run from Claude mobile.
- **Not investment advice.** Single-analyst research on public equities, with no independent review.

## 9. Workarounds

- *Stale figures:* re-run the analysis into a new dated folder. Never edit a prior one.
- *Table drift:* cross-check the table against memo Section 1 and the Verdict section before committing; AGENTS.md verification gate 3 requires it.
- *Missing build scripts:* the memos and models remain readable as delivered. Regenerating requires authoring a new script against the current memo structure — treat it as a new analysis, not a repair.
- *`$NOW` contract break:* fix it on the next `$NOW` run by creating `$NOW/$NOW-{date}/` and moving the July files into `$NOW_Archive/`. Do not retro-move them now — that would rewrite history the memos reference.
- *Legacy naming:* `SG` and `TRMB` migrate to `$TICKER` on next touch, per AGENTS.md. No bulk rename.
- *Ignored ticker folders:* `git add -f '$TICKER/'` once per approved ticker; it stays tracked afterward. Verify with `git status --porcelain` before finishing a run.
- *Mobile limitation:* run the build in a desktop session. See CLAUDE.md.

## 10. Build Notes

- **Runtime:** Python 3.9+ with `openpyxl` for models; Node.js with the `docx` package for memos. Charts are generated with `matplotlib` where a chart is produced.
- **Install:** `pip install openpyxl --break-system-packages` and `npm install -g docx`. The `--break-system-packages` flag is needed on macOS system Python.
- **Platform:** developed and tested on macOS (Darwin 25.x). Not validated on Windows or Linux.
- **Shell safety:** every path containing `$` must be single-quoted in the shell, and build scripts must quote their own output paths. This is the most common source of silent failures — an unquoted `$BROS` expands to nothing and the file writes to the wrong place.
- **Never overwrite a dated analysis.** A re-run gets a new folder. This is enforced by convention, not by tooling.
- **Staging:** stage named paths only. Never `git add -A`, `git add .`, or `git commit -a` — see the staging rules in AGENTS.md and CONTRIBUTING.md.
- **Push:** standard `git push`. If sandbox network restrictions block it, use the GitHub Contents API per CONTRIBUTING.md — `GET` the current `sha` before any `PUT` that updates an existing file, or the API returns 409.
